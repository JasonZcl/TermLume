# 工作区服务端 0.9.0

本版将工作区 API 迁移至开源 ABP Framework 10.7.1，使用 .NET 10、ABP 模块、Autofac、应用服务和 MVC 控制器。桌面客户端维持 0.8.1，继续使用原来的 `/v1/workspace` 接口，现有安装包可直接连接。

所有账号和工作区继续使用 `termlume` 数据库。保留原三份 SQL 迁移，业务表、RLS、成员权限、设备撤销、历史和审计保持兼容。认证由 Aegis-IAM 负责，访问令牌签名及实时 UserInfo 校验均保留。API 只返回既有安全错误格式，并关闭框架参数审计及额外基础设施路由。

新增 `004_log_retention.sql`，将服务端同步活动日志及审计统一保留 7 天。活动日志按服务端接收时间计算，审计按生成时间计算；查询立即排除过期记录，API 启动时及每小时清理，包括不活跃账号。通过固定期限的安全定义函数清理，运行角色仍不能任意修改或删除审计；本机活动日志仍按 2,000 条上限保留。

## 部署到本机 Docker

先启动上一级 Aegis-IAM 项目的 Docker 测试环境，在本仓库执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./tools/Publish-WorkspaceDocker.ps1
Invoke-RestMethod http://127.0.0.1:18741/healthz
docker compose -f docker/compose.workspace.yml ps
```

脚本备份已有数据库，构建 `termlume-workspace-api:0.9.0`，通过一次性迁移容器检查已应用迁移，再启动常驻 API 并等待健康。备份保存在 `.local/backups/`，密码只在 `.local/` 的受限配置文件中，以只读挂载进入容器。服务绑定本机 `127.0.0.1:18741`，Docker 引擎运行时按 `unless-stopped` 策略恢复服务。

只更新后续源码时，可重新运行同一脚本。查看状态和日志：

```powershell
docker compose -f docker/compose.workspace.yml ps
docker compose -f docker/compose.workspace.yml logs --tail 100 workspace-api
```

停止服务可运行 `docker compose -f docker/compose.workspace.yml down`，业务数据库保留。其他设备访问需要部署可达的 HTTPS API 和 IAM，并调整桌面端服务配置。

## 验证

```powershell
node --test tests/workspace-api.integration.cjs
$env:TERMLUME_TEST_DOCKER_IMAGE = 'termlume-workspace-api:0.9.0'
node --test tests/workspace-api.integration.cjs
Remove-Item Env:TERMLUME_TEST_DOCKER_IMAGE
```

同一集成套件支持本机可执行文件及实际 Docker 镜像，覆盖 24 项检查：ABP 路由范围、MVC 严格输入及错误协议、真实 PostgreSQL 持久化、JWT 与实时授权、RLS、成员角色、设备撤销、并发、历史、审计、隐私及进程重启。容器测试使用临时容器和可清理的独立测试身份，复用现有数据库。

提交前复核修复了日志详情为 `null` 时触发 503 的输入处理缺陷，并将 `capabilities` 版本与健康接口统一。代码补充了认证、RLS 事务、迁移校验和错误处理的边界注释，Git 与 Docker 构建上下文增加了本地配置、环境文件、备份及私钥的排除规则。完整记录见 [2026-11-20 安全检查](../security-review-2026-11-20.md)。

运行时安全基线更新到 .NET / ASP.NET Core 10.0.15，Docker 运行镜像包含 Ubuntu apt 2.8.4ubuntu0.1 补丁。发布脚本构建时刷新基础镜像，避免沿用本地旧层；桌面安装脚本也允许 API 独立版本。

框架版本及集成方式参考 [NuGet ABP MVC 10.7.1](https://www.nuget.org/packages/Volo.Abp.AspNetCore.Mvc/10.7.1) 和 [ABP 官方应用接入说明](https://abp.io/docs/latest/get-started/empty-aspnet-core-application)。
